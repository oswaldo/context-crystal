# Context Crystal v1.3.0 — Inclusion

Context Crystal `v1.3.0` ("Inclusion") represents a major evolutionary leap for Context Crystal, expanding the foundational context lattice with **Modular Spec Extensions**, **Multi-Entity Inter-Crystal Communications**, **CEP-0002 Media & Multi-Modal Provenance**, **Granular DAG Node Inspection & Uncapped Hydration**, **Complete Storage CRUD Lifecycle Symmetry**, and **Unified MCP Ergonomics**.

In mineralogy and crystallography, an *inclusion* is any material or characteristic phase enclosed within a crystal during its formation. Far from being a flaw, an authentic inclusion provides definitive, tamper-proof provenance—revealing the physical environment, thermal history, and geological lineage of the gemstone. In `v1.3.0`, this natural phenomenon inspires the encapsulation of domain-specific modular extensions, inter-entity mailboxes, and multi-modal assets securely enclosed within individual crystal boundaries, establishing immutable provenance while preserving an ultra-lean, microsecond-fast foundational runtime.

---

## 🚀 What's New & Improved

### 🧩 Modular Spec Extensions Architecture (`ccrystal ext`)

- **Domain-Specific Extensibility Without Core Bloat:** Context Crystal's foundational binary remains microsecond-lean and zero-dependency, while enabling rich, specialized domain metadata (media pipelines, spatial graphs, external sensors) via decoupled extension envelopes stored under `.ccrystals/<id>/extensions/<ext-id>/`.
- **Three-Tier Scope Resolution:** Extensions and their companion skills resolve dynamically across three distinct operational layers:
  1. **Crystal Scope:** Local domain state specific to a single endeavor (`.ccrystals/<id>/extensions/`).
  2. **Cave Scope:** Workspace-wide schemas and skills shared across all workspace crystals (`.ccrystals/extensions/`).
  3. **Host Scope:** Global user or agent extensions shared across all local workspaces (`~/.ccrystals/extensions/`).
- **Embedded Extension Skills (`ccrystal ext skill <name>`):** Modular extensions can package their own operational `SKILL.md` instructions. Autonomous AI entities can discover, read, and invoke extension-specific capabilities on demand with zero learning curve.
- **Built-in Reference Extensions:** Ships with built-in native support for `comms` (inter-entity crystal messaging) and `sample_runner` (demonstration and integration verification).

### 💬 Multi-Entity Crystal Comms (`ccrystal comms`)

- **Inter-Entity Messaging & Mailbox Hygiene:** Autonomous agents and human collaborators can exchange targeted messages directly across crystal boundaries:
  - Directed entity-to-entity messaging (`toEntity`).
  - Broad broadcast messaging (`*`).
  - Topic-based broadcast channels (`#channel`).
  - Named collaborator group routing (`@group`).
- **FIFO Mailbox Limits & Pruning:** Mailboxes feature automated FIFO retention bounds (defaulting to 1,000 messages) and explicit hygiene commands (`ccrystal comms clear`, `ccrystal comms ack`) to keep context beams microsecond-fast and lightweight.
- **Causal DAG Reflection (`--record-dag`):** Communications can optionally reflect directly into the crystal's causal Directed Acyclic Graph (DAG) as `human_prompt` or `agent_reasoning` nodes, creating an auditable provenance chain of inter-agent deliberation.
- **Full MCP Server Integration:** Dynamic multi-entity communication available to AI agents via `crystal_extension_comms` and generic `crystal_extension_call`.

### 🎬 CEP-0002: Media & Multi-Modal Provenance Extension

- **Multi-Modal Production Metadata:** Formalizes declarative provenance tracking for creative media pipelines (video, audio, graphics, speech):
  - Ingestion manifests with SHA-256 asset checksums, duration, frame rates, and sample rates.
  - Video and audio segment timelines with edit points, acoustic silence-valley removal, and loudness normalization bounds (-16 LUFS stereo / -14 LUFS multi-channel).
  - Trilingual safe-zone subtitles and captions (`pt-BR`, `es-ES`, `en-US`).
  - Multi-aspect ratio export manifests (16:9 widescreen, 9:16 vertical reels/shorts).
  - Physical and removable SSD archival lifecycle tracking.
- **Declarative Web-Native Motion Engine (Hyperframes Steering):** Explicitly guides AI agents toward declarative HTML/CSS motion compositions (Hyperframes) for title cards, overlays, and lower-thirds, eliminating brittle imperative scripting and token-burning filtergraphs.
- **Decoupled Architecture:** Core Context Crystal does not bundle heavy video or audio decoders; creative media pipelines remain fully modular drop-ins.

### 🔍 Granular DAG Node Querying & Uncapped Hydration (`ccrystal node`)

- **Dedicated Node Query Engine (`ccrystal node list`, `ccrystal node show`):** Developers and autonomous agents can inspect the causal DAG directly without parsing raw JSON files:
  - Filter nodes by kind (`human_prompt`, `agent_reasoning`, `tool_execution`, `checkpoint`, `branch`, `resolution`).
  - Filter by author/entity ID (`--author <name>`).
  - Inspect individual node payloads, metadata, and causal parent links with syntax highlighting and formatted envelopes.
- **Uncapped Hydration (`ccrystal hydrate --all`):** Hydrate the complete, unpruned causal history of a crystal for deep retrospectives and comprehensive audits, bypassing default sliding-window context limits.
- **Deep MCP Search Scoping:** The `crystal_search` MCP tool now supports targeted filtering scoped to a specific crystal (`crystal_id`), enabling precise cross-session lookups.

### 🔄 Complete Storage CRUD Lifecycle Symmetry

- **Artifact Unregistration (`ccrystal artifact unregister`, MCP `crystal_artifact` action `unregister`):** Remove obsolete or ephemeral artifact registrations from crystal metadata without leaving orphan records.
- **Task Cancellation & Deletion (`ccrystal task cancel`, `ccrystal task delete`, MCP `crystal_task_transition` action `cancel`):** Cleanly mark in-flight tasks as cancelled or prune stale tasks, maintaining an accurate and up-to-date picture of workspace state.

### 🛠️ Consolidated MCP Server Ergonomics & Observability

- **Uniform `verb_noun` Tool Architecture:** Consolidated tool names across the native Model Context Protocol (MCP) server interface (`crystal_init`, `crystal_hydrate`, `crystal_checkpoint`, `crystal_task_transition`, `crystal_goal_transition`, `crystal_artifact`, `crystal_prune`, etc.) for consistent agent discovery.
- **First-Class Operational Learning (`crystal_lesson`):** Record, update, and resolve friction logs and operational lessons directly within active crystal memory.
- **Self-Hydrating Tool Responses:** MCP mutations (`crystal_checkpoint`, `crystal_task_transition`, etc.) automatically return an updated context beam, eliminating redundant turn roundtrips and token consumption.
- **Extension Observability in Dashboard (`ccrystal stats`):** The stats command reports comprehensive extension metrics, including installed extensions, mailbox counts, and creative media asset accounting (source footage counts, durations, and byte totals), with zero external tracking.

## 📦 Installation Options

- **Coursier (Universal Zero-Install across Windows, macOS, Linux, BSD):**

  ```bash
  # Instant launch via official Coursier contrib channel:
  cs launch --contrib ccrystal

  # Or install globally to your PATH:
  cs install --contrib ccrystal
  ```

  *(Also available directly via immutable Maven Central coordinates: `cs launch io.github.oswaldo:ccrystal-cli_3:latest.release -- --help`)*

- **Universal POSIX Installer (Native Linux / macOS):**

  ```bash
  curl -fsSL https://raw.githubusercontent.com/oswaldo/context-crystal/main/install.sh | sh
  ```

- **Homebrew (macOS / Linux):**

  ```bash
  brew install oswaldo/context-crystal/ccrystal
  ```

- **Prebuilt Standalone Binaries:**
  Optimized native executables compiled with Thin LTO are attached to the GitHub release for `linux-x86_64`, `linux-aarch64`, `macos-aarch64`, and `macos-x86_64`, along with cryptographic `SHA256SUMS`.
