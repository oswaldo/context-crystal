# Specification: Native MCP Server Consolidation, TDQS Optimization & Agent Ergonomics

## 1. Overview & Motivation

Context Crystal features an embedded stdio Model Context Protocol (MCP) server. While currently functional (17 registered tools with a Grade B 3.2/5.0 on Glama TDQS), several architectural and ergonomic gaps impede optimal AI coding assistant usage:
1. **Missing First-Class Lesson Management:** Lessons learned can be recorded through CLI or batch scripts, but lack dedicated MCP tool endpoints (`record`, `resolve`, `list`).
2. **Turn Latency & Inspection Overhead:** When completing tasks (`crystal_task_transition`), the tool returns minimal status strings, forcing agents to burn extra tool calls reading `tasks.md` or `crystal.json` to inspect what work remains.
3. **Eager vs. Lazy Promotion:** Agents running in environments like Antigravity, Gemini CLI, or Claude Desktop must lazily inspect on-disk `.json` schemas instead of receiving high-frequency lifecycle tools in-context.
4. **Naming Consistency & Quality Score:** Achieving a verified Grade A (4.5+/5.0) on Glama TDQS requires complete CRUD coverage, uniform `verb_noun` nomenclature, and high-fidelity tool documentation.

This track establishes:
- A dedicated first-class `crystal_lesson` MCP tool.
- Self-hydrating lifecycle responses projecting updated task checklists and context anchors directly into tool results.
- Uniform `verb_noun` naming conventions across all native MCP tools with strict cutover.
- Eager tool registration configurations and compact `instructions.md` cheatsheets generated by `ccrystal agent install`.

## 2. Functional Requirements

### 2.1 First-Class Lesson Tool (`crystal_lesson`)
- Implement `crystal_lesson` in `DefaultMcpHandler.scala` with actions:
  - `record`: Records a lesson learned (`summary`, `context`, optional `id`) into the specified crystal.
  - `resolve`: Marks an open lesson as resolved or addresses it with an action summary.
  - `list`: Lists active/open lessons for a crystal or across the entire cave.
- Return structured Markdown output detailing lesson ID, timestamp, and resolution state.

### 2.2 Self-Hydrating Lifecycle Responses
- **`crystal_task_transition`:** When a task is marked `done`, `in_progress`, or newly added:
  - Return the operational confirmation message.
  - Automatically append the full rendered Markdown task checklist (`- [x] ...`, `- [ ] ...`), completion count (`X/Y completed`), and goal summary.
- **`crystal_checkpoint`:** When appending a checkpoint node:
  - Return confirmation accompanied by the current DAG head and task progress snapshot.

### 2.3 Uniform Tool Naming & Surface Hardening
- Enforce clean, predictable `verb_noun` tool signatures across the MCP surface:
  - `crystal_init`: Crystal inception.
  - `crystal_search`: Cave queries and temporal filtering.
  - `crystal_stats`: Cave footprint metrics and token savings.
  - `crystal_checkpoint`: DAG node checkpoint appending.
  - `crystal_task_transition`: Task lifecycle updates.
  - `crystal_goal_transition`: Crystal goal state changes.
  - `crystal_transient_lease`: Transient resource leases.
  - `crystal_slice_fork`: Sub-DAG fragment slicing and child forks.
  - `crystal_prune`: Crystal deletion and cold storage purging.
  - `crystal_artifact`: Virtual/physical artifact registration and unlinking.
  - `crystal_hydrate`: Context beam hydration.
  - `crystal_triage`: Lifecycle hygiene triage.
  - `crystal_archive`: Archiving to cold storage.
  - `crystal_unarchive`: Restoring from cold storage.
  - `crystal_melt`: Sub-DAG checkpoint melting.
  - `crystal_connect`: Directed lattice bond management.
  - `crystal_lesson`: First-class lesson lifecycle management.
  - `crystal_batch`: Batch script execution.
- Strict cutover: Deprecated alias parameters eliminated in favor of canonical parameters.

### 2.4 Eager Harness Auto-Configuration & Instructions Generation
- Update `ccrystal agent install` to configure high-frequency tools (`crystal_checkpoint`, `crystal_task_transition`, `crystal_hydrate`, `crystal_archive`, `crystal_lesson`) as **Eager** tools where supported.
- Generate compact `instructions.md` call cheatsheets in client tool directories to eliminate lazy disk schema inspection.

## 3. Non-Functional Requirements & TDQS Score Target
- **Glama TDQS Grade A (4.5+/5.0):** Comprehensive parameter schemas, explicit return types, and documented failure modes.
- **Zero Reflection & Instant Response:** Handler remains pure non-reflective Scala Native stdio JSON-RPC 2.0 with sub-5ms response latency.
- **Zero Secret Leakage:** Tool arguments and rendered self-hydration beams must strictly redact credentials and avoid emitting raw private payloads.
